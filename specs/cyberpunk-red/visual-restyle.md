# Spec: Visual Restyle

## Status
Implemented

## Summary
A visual-only restyle of the whole app to a dark cyberpunk aesthetic (near-black surface, neon red/cyan accents, sharp angular corners, uppercase Chakra Petch display type), sourced from a design handoff (`ui-handoff/`, not checked into the app's own source — reference material only). No layout, structure, component composition, or JSX element tree changed anywhere — every existing class name and DOM structure stays exactly as-is; only CSS property *values* (colors, borders, radii, shadows, font-weight/transform) changed, plus a few new `:hover`/`:focus`/`:disabled` states that didn't have explicit styling before.

## Requirements
- [x] `client/src/index.css` and `client/src/App.css` are restyled to match the handoff's design tokens (colors, typography, shape/elevation) — see Decisions for the exact token values
- [x] The app becomes dark-only — the existing `@media (prefers-color-scheme: dark)` light/dark branch is removed, its values merged into `:root` as the only theme
- [x] No component's layout, sizing, or structure changes — same elements, same classes, same DOM nesting everywhere
- [x] Everything not covered by the handoff (because it postdates the reference mockup) keeps working and gets the same visual treatment applied to it: the typing indicator (dots + "is typing..." text) is restyled in place, not removed or altered in behavior
- [x] Two new, explicitly non-functional UI elements from the handoff mockup are added — see [ready-for-dm.md](../ready-for-dm.md), a separate spec since it's a distinct (non-styling) piece of scope

## Decisions
- **Source of truth: the reference CSS files, not the HTML mockup's inline styles.** `ui-handoff/reference/index.css` and `App.css` are restyled copies of this app's real files (per the handoff's own README, "high-fidelity... implement as specified") and were merged in near-verbatim. `ui-handoff/reference/Cyberpunk RED UI Preview.dc.html` is explicitly marked "illustrative-only... not a component to port" and was used only to see the two new ready-status elements in context (see the other spec) — not as a second, competing source of CSS values.
- **One real discrepancy found between the two, resolved in favor of the CSS file**: the HTML mockup hardcodes the SP bar's fill to cyan (`#2fe4ff`) at a non-zero SP value, but the actual reference `App.css` leaves `.hp-bar-fill.hp-neutral` as plain gray, unchanged — and SP is *always* rendered with `colorClass="hp-neutral"` in this app regardless of value, per an explicit earlier product decision ([character-sp.md](character-sp.md): "no color changes, no wound state"). Since the CSS file (the stated authority) doesn't add SP-specific coloring, and the mockup is only illustrative, SP stays permanently gray — the mockup's cyan SP bar was read as a one-off illustrative flourish, not an instruction to recolor SP. Flagged to the user in case that reading is wrong.
- **Design tokens** (from the handoff's own token table, applied via CSS custom properties in `:root`): `--bg: #0a0b10`, `--bg-raised: #101219` (new token — inputs/cards/bubbles previously used `var(--bg)` for these; the restyle introduces a distinct slightly-lighter surface for them), `--border: #262a38`, `--text: #8b93a7`, `--text-h: #edf1f7`, `--accent: #ff2b4d` (red), `--accent-bg`/`--accent-border` (red, translucent), `--accent-2: #2fe4ff` (cyan, new token — previously there was no secondary accent color), `--accent-2-bg` (cyan, translucent), `--heading: 'Chakra Petch', sans-serif` (previously a plain system-font stack — this was the exact fix already made in an earlier session for the modal-heading font mismatch; the redesign formalizes it as a real design decision rather than a bugfix).
- **Background wash**: two faint radial gradients (red top-left, cyan top-right) layered behind `body`, `background-attachment: fixed` — purely decorative, doesn't affect any layout.
- **Shape**: border-radius reduced app-wide from ~6-10px to 2-3px (sharp/angular). Perfectly circular elements (`.spinner`, `.typing-dots span`, the ready-status dots) keep `border-radius: 50%` — the "sharper corners" token applies to rectangular UI chrome, not circles.
- **Elevation/interaction feedback**: hover states on primary buttons (Send, Ask the DM, Roll, login Enter) get a colored glow (`box-shadow: 0 0 16px var(--accent-border)`) instead of a flat background swap; icon buttons (Description/Gear/Map, message edit/delete) get a smaller cyan glow (`0 0 12px var(--accent-2-bg)`) on hover. Selected/hovered sidebar rows and the Party row get a 2px accent-colored left border instead of (in addition to) a background tint.
- **Typing indicator restyle**: `#messages li.typing-indicator`/`.typing-dots`/`@keyframes typing-bounce` (see [typing-indicator.md](../typing-indicator.md)) needed no color-value changes at all — the dots use `background: currentColor` (inherits whatever the surrounding muted text color is, automatically correct under the new palette) and the block has no borders/backgrounds of its own. Carried over unchanged, in its same position in the file (right after the DM "awaiting reply" spinner), since the reference file — built before this feature existed — has nothing to diff it against.
- **Font weight 600 added** to the Chakra Petch Google Fonts `@import`, alongside the existing 400/500/700 — used by several of the new uppercase button/label treatments.

## Open Questions
Whether the SP bar should actually pick up the cyan coloring shown in the mockup screenshot — currently left gray per the reasoning above; easy to revisit if that reading was wrong.
