This project uses vibe-coding, not spec-driven development — implement directly from conversation context, no spec-before-code requirement. specs/ is a flat folder (no subfolders) of per-feature reference docs kept from before the switch — useful "why" context (decisions, tradeoffs, bugs found while building) worth checking when relevant, but historical reference only: not a gate on starting work, and not something that needs creating or updating for new work. steering/product.md and steering/tech.md are the stable, evolving product/tech overview — read them before making changes to this project.

Dev servers: before starting the server (`npm run dev` in server/, port 3001) or client (port 5173) for testing/verification, check first whether one is already running (e.g. `curl localhost:3001`) and reuse it rather than starting a second one — the user's own terminal is the default instance, since they need it running there for feedback/visibility. It's fine to spin up your own separate instance during development if you need one (e.g. to avoid disrupting a live session), but always shut it down once you're done, whether or not the user's instance was also running at the time — never leave a Claude-started dev server up, so it can't collide with the user starting (or already running) theirs later.
