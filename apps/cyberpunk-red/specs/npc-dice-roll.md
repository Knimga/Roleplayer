# Spec: NPC Dice Roll (MCP Tool)

## Status
Implemented

## Summary
An MCP tool lets Claude roll dice for enemies/NPCs itself — for opposed-roll scenarios (attacker vs. defender) and for general rolls like weapon damage, where the DM needs a real result, not narrated color. Players always roll their own skill checks when Claude asks for one; this tool is for the DM's own rolls only. General-purpose dice math (variable count/sides/modifier) rather than a fixed 1d10 skill-check shape — the same tool covers both opposed skill checks and damage rolls.

## Requirements
- [x] A new MCP tool (alongside the existing lore tools in [lore-file-access.md](lore-file-access.md)'s server) lets Claude roll for an NPC/enemy
- [x] Inputs: number of dice (integer), sides per die (6 or 10 only), and a single combined modifier (integer) to add to the roll result
- [x] Returns three things: the final total, a human-readable summary string that reflects the actual dice rolled (e.g. `"Rolled 18! (1d10 (7) + 11)"` for a skill check, `"Rolled 15! (4d6 (2+5+3+1) + 4)"` for damage), and an explicit crit indicator (success / failure / neither)
- [x] This tool is never used for player rolls — only Claude calling it on behalf of NPCs/enemies

## Decisions
- **Same MCP server as lore**: a new tool (`roll_dice` or similar — no longer NPC-check-specific in shape, though still DM/NPC-only in usage) registered on the existing in-process MCP server ([lore-file-access.md](lore-file-access.md)), not a separate server — same architecture, same `claude.js` tool-use loop already built, just another tool in the list.
- **Crit logic only applies to the classic single-d10 skill-check shape** (`numDice === 1 && sides === 10`): natural 10 rerolls-and-adds (exploding on repeated 10s), natural 1 rerolls-and-subtracts (exploding on repeated 1s), per Cyberpunk Red's core mechanic. Any other combination (multiple dice, or d6s — e.g. weapon damage) has no crit concept in CPR's rules, so the crit indicator is just `null`/neither for those. This is a judgment call inferred from CPR's rules rather than something explicitly stated in the request — flagging in case damage rolls should have their own crit-injury mechanic later.
- **Crit handling lives in the tool, not the prompt**: real randomness for crit rerolls is generated by code, not left to the LLM to notice a 10/1 and decide to call the tool again. The tool returns a dedicated crit field (e.g. `critResult: "success" | "failure" | null`) *in addition to* the summary string, so callers (Claude's narration, and later any UI that surfaces rolls) can react to a crit without parsing text.
- **Stateless**: no character data model involved — the caller (Claude) supplies the modifier as a plain integer already known from context/narration, not looked up from a saved character sheet (no character builder exists yet).

## Open Questions
- Should damage-style rolls (multiple dice / d6s) have their own critical-injury mechanic down the line, separate from the skill-check crit logic? Not building this now — just flagging that "no crit" for those rolls is an assumption, not a confirmed rule.
